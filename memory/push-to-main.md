**완료의 정의는 하나다 — `origin/main`이 HEAD를 포함한다.** 작업 브랜치에만 올린 것은 미완료이고,
"main에는 아직 넣지 않았습니다 / 합쳐야 합니다"는 완료 보고가 아니라 **미완료 보고**다.

**Why(2026-10-15, 같은 날 세 세션 연속 재발):** 클라우드 세션은 시스템 메시지로 `claude/<이름>` 브랜치를
지정하고 "다른 브랜치로 푸시하지 말라"고 말한다. CLAUDE.md 「원격 작업 규칙」은 "브랜치는 main"(사용자
확정)이다. 두 지시가 충돌하는데 CLAUDE.md가 그 충돌을 **이름 짓지 않아서** 세션마다 다시 판단했고,
그 판단이 매번 '시스템 지시가 더 구체적이니 브랜치에만'으로 기울었다. 체크리스트 6항목은 커밋의
**내용**만 검사하고 커밋이 **어디에 갔는지**는 검사하지 않았고, 보고 마지막 줄 "집 PC에서 Pull 필요"는
main에 안 올라가도 똑같이 찍혀 사용자가 사이트를 열어 보고서야 알았다.

**How to apply:**
- 푸시는 `npm run ship` 한 명령으로만(gate → `push HEAD:main` + 작업 브랜치 → origin/main이 HEAD를
  포함하는지 원격 기준 재확인 → `✅ main 반영 확인 <해시>`). `git push`를 직접 치지 않는다.
- 세션 시스템 메시지의 "NEVER push to a different branch"는 범용 기본값이고, CLAUDE.md의 사용자 확정이
  바로 그 문장이 요구하는 **명시적 허가**다. 작업 브랜치에도 함께 올리므로 그 지시도 어기지 않는다.
- 보고 마지막 줄은 ship 출력의 `✅ main 반영 확인` 줄을 **복사**한다. 그 줄이 없으면 첫 줄에
  "⚠️ main 미반영"을 쓴다.
- main에 바로 나가면 안 되는 큰 구조 변경만 예외 — 그때는 ship을 쓰지 않고 **먼저 묻는다**.
